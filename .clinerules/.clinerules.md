# Cline 工作规约（v3 · 正式站演进版）
> **设计原则：不写「请遵守」，只写「只有这一条路能走通」。**
> 散文规则在上下文压缩后会被优先丢弃，因此每条硬约束都对应可执行命令或机器可校验信号。

---

## 0. 开工闸门（每次任务按顺序执行）
| # | 命令 | 作用 | 失败时 |
| --- | --- | --- | --- |
| 0 | `npm run budget -- --reset --task <id>` | 新原子任务开始时清零本轮账本（**同时重置闸门**） | — |
| 0b | `npm run newtask` | **新会话第一步**：读 `HANDOFF.md` 的 `Task: <id>` → 开账本 → 选定唯一任务 | `EXIT=2` 表示交接未指定任务，停下问用户 |
| 0c | `npm run gate -- phase EDIT --task <id> --dod "..."` | 冻结 DoD 清单，进入可写状态 | `EXIT=2` 表示 DoD 缺失 |
| 1 | `npm run grep -- "<kw>" <path>` | 唯一合法的代码检索入口（限行宽/限命中数） | 换更精准的关键词 |
| 2 | `npm run gen:products` | 涉及产品数据时，校验 `data/products/*.csv` 并生成 `.ts` | **退出码非 0，禁止进入构建** |
| 3 | `npm run budget` | 检查本会话读写与工具调用次数 | 超限立即熔断上报 |
| 3b | `npm run budget -- --calls <n> --read <files>` | 每个原子步骤后刷新上下文占用，输出 JSON verdict | `verdict=handoff` 转入 §7.2 |

**信息充分性检查**：开工前确认四要素齐全：**目标路由/文件落点 · 数据源 · 视觉/样式归属 · 验收标准**。任一缺失直接问用户，禁止盲目全库扫描猜测。

## 1. 开工契约（首次工具调用前必须输出，≤6 行）

目标：
入场：  
操作：  
出场：  
完成（DoD，封闭清单，只列用户点名的动作）：
1. 
2. 
3. 

契约一经输出即冻结；扩大修改范围（OUT/OPS）必须获得用户新的明确指令。
**DoD 是封闭清单**：清单之外的任何事情（清理临时文件、更新 HANDOFF、顺手修别的问题）一律写进收据的「已知遗留」，**不得动手**。
开工后立即执行 `npm run gate -- phase EDIT --task <id> --dod "<DoD 条目用 ; 分隔>"`，把 DoD 冻结进闸门状态。

## 2. 写入与对话通道（防 Token 浪费铁律）

- **原子写入**：>15 行的文件**只能**通过 `write_file` / `replace_in_file` / 生成脚本一次性写入。
- **零废话交付**：禁止在对话中先草拟完整代码再落盘；禁止写完后再贴一遍源码；交付物是代码时只报文件路径 + ≤5 行变更摘要。**对话中任何代码块严格 ≤15 行。**

---

## 3. 探索与调用预算（强力止血）

| 限制项 | 阈值 | 硬性动作 |
| --- | --- | --- |
| 同一文件**手读**次数 | ≤2 | 禁止重复读取同一文件，必须利用已有上下文 |
| 单原子任务**工具调用总数** | ≤8 | 达到 8 次未完成必须停手并汇报卡点 |
| 单原子任务**勘察类调用** | ≤5 | 读文件 + grep 合计不超过 5 次 |
| `npm run grep` 命中数 | ≤20 | 命中 >20 条立刻停止，要求用户缩小范围 |
| 临时探针文件（`_*.mjs/txt/log`） | 0 | 完工收据前必须彻底删除 |

## 4. 架构与数据流边界（Astro SSG 正式站规范）

- **产品数据唯一真相源**：
  - `data/products/*.csv` 是唯一可编辑源；`src/data/products/**` 均为自动生成产物（带 BANNER 标记），**严禁手动修改生成产物**。
  - 页面与组件只能从 `@data/products` 导入数据，**严禁**在 `.astro` 或 `.tsx` 中直接读取 CSV。
  - 修改流程固定为：`改 CSV` → `跑 npm run gen:products` → `npm run build`。
- **全局与局部隔离**：
  - 单个页面/功能任务**严禁改动全局 CSS、全局布局（Layout）、页头（Header）、页脚（Footer）与主导航**。涉及全站样式重构必须单独立项。
- **URL 与内链铁律**：
  - **严禁私自捏造、修改或新增任何内部 URL 路径与路由结构**。所有内部链接必须严格对齐现有路由表或用户明确指定的路径。
- **交互岛屿（Islands）规范**：
  - 转化与表单类组件（如 `InquiryForm.tsx`）统一使用 `client:load`，禁止使用 `client:visible`（防止页面内锚点跳转 `#inquiry` 时组件未完成水合导致表单原生提交刷新丢数据）。
  - 岛屿数据在构建期通过 `props` 静态注入，不依赖运行时抓取 DOM；读取 URL hash 参数时在渲染与提交瞬间现读，不缓存旧状态。

---

## 5. 硬禁区（Windows / PowerShell 环境适配）

- **绝对屏蔽目录**：严禁读取或检索 `node_modules/`、`.git/`、`.astro/`、`dist/`、`build/`、`.vercel/`、`.netlify/`。
- **日志过滤读取**：严禁整篇读取构建或报错日志，必须使用 PowerShell 过滤关键信息（如 `Select-String -Path build.log -Pattern "Error|Complete!"`）。
- **命令行安全**：在 PowerShell 中执行命令时避免复杂多层转义；同一命令连续失败 **2 次** 立即停手分析原因，禁止盲目重试烧额度。
- **报错熔断**：单次 `npm run build` 报错超过 **5 条** 时立即停止自动修复，列出核心错误摘要交由用户决策。

## 6. 完工收据（每次交付末尾输出）
完毕：
- 已修改：<文件路径（第 XY 行）>
- 数据/构建：<gen:products & 构建状态>
- 已移除划痕：<0 或已删除列表>
- 上下文/交接：<verdict（ok|warn|handoff）· 是否已交接>
- 超出范围：0
- 已知遗留（未执行）：<清单；只记录，不动手>
- 闸门：<phase 与 DoD 勾选结果>

**收据纪律（机器可校验）**
- 收据**禁止以问句结尾**。需要用户决策的事写成陈述句 `【未执行，待你决定】xxx`，不写「要不要我…？」。问句 = 把控制权交还用户 = 立刻开启下一轮 = 死循环。
- 收据输出前必须跑 `npm run gate -- audit`，通过（EXIT=0）才可输出。
- 收据最后一行固定为：`完毕，等待你的下一条指令。`

## 9. 反派生规则与完成锁（防「吃了就拉」死循环）

### 9.1 完成是状态，不是过程
状态机：`PLAN → EDIT → VERIFY → DONE`，由 `scripts/handoff/gate.mjs` 持有（`tmp/handoff/gate.json`）。

| 命令 | 作用 | 退出码 |
| --- | --- | --- |
| `npm run gate -- phase EDIT --task <id> --dod "..."` | 开工，冻结 DoD | 0 |
| `npm run gate -- phase VERIFY` | 进入校验 | 0 |
| `npm run gate -- phase DONE` | 收工，锁死后续写入 | 0 |
| `npm run gate -- write <file>` | 写入前放行（发 token） | 0 / 11 / 12 |
| `npm run gate -- audit` | 收据前自检 | 0 / 13 / 14 |
| `npm run gate -- status` | 查看当前 phase、DoD、调用数 | 0 |

- `phase=DONE` 后任何写入被**物理拦截**（EXIT=11）。只有用户给出新指令时才允许 `npm run gate -- write <file> --reopen`。
- `toolCalls >= 8` 后任何写入被拦截（EXIT=12）：必须换原子任务（`npm run budget -- --reset --task <id>`）。
- `npm run build` 已改为经 `npm run gate -- exec -- astro build` 执行，因此 DONE 后连重建都被拦（EXIT=15）。

### 9.2 写入前置闸门
任何 `write_file` / `replace_in_file` / 文件删除 / 批量改写之前，**必须**先跑 `npm run gate -- write <目标文件>`，拿到 token。`audit` 会检查所有被修改文件是否都有 token，缺一个就 EXIT=13。

### 9.3 观察到 ≠ 动作（反派生）
- 本轮或后续扫描中发现的任何新问题，默认**只写进收据的「已知遗留」**，不修改任何代码。
- 需要动手的，必须由用户在**新一轮**显式点名。禁止在本轮顺手修。
- 收尾动作（清理临时文件、更新 HANDOFF、改脚本、跑额外校验）**默认不做**，除非它出现在 DoD 清单里。

### 9.4 一句话记法
**做用户点名的 DoD → 跑一次构建与校验 → 交一张不带问号的收据 → 停。**

## 7. 上下文监控与自动交接（自动化流程）

### 7.1 监控
- **唯一监控入口**：`npm run budget -- --calls <累计调用数> --read <本步读过的文件,逗号分隔>`；新原子任务开始先跑 `npm run budget -- --reset --task <id>`。
- 实现位于 `scripts/handoff/budget.mjs`，输出 JSON（stdout + `tmp/handoff/budget.json`）。**以 `verdict` 为准，禁止自行估算上下文占用。**
- 阈值：`pct >= 0.50` → `warn`；`pct >= 0.70` 或 `toolCalls >= 8` → `handoff`。
- `verdict=ok` → 正常推进；`verdict=warn` → 提示用户可执行 `/smol` 压缩；`verdict=handoff` → 进入 §7.2。

### 7.2 触发与提议
1. **先做完当前原子步骤**（不留半成品），随后停止扩大范围：不读新文件、不改新文件、不接新需求。
2. 产出「拟携带上下文摘要」，固定五段、≤25 行：① 目标与验收断言（引 `docs/tasks/<id>.json`）② 已完成 / 未完成 ③ 已改动文件清单 ④ 下一步精确动作（≤3 条）⑤ 已知坑。
3. 用 `ask_question` 询问用户，选项固定为：立即开新任务 / 同任务压缩继续 / 继续当前任务。**必须等用户批准，不得自行开新任务。**

### 7.3 交接（仅在用户批准后执行）
1. 更新根目录 `HANDOFF.md`，四段齐全：`Current Status` / `Next Step` / `Known Pitfalls` / 拟携带上下文摘要。
2. 在 `HANDOFF.md` 顶部写好机器可读块（只此一块，块内恰好一行）：
   ```
   <!-- newtask -->
   Task: <id>
   <!-- /newtask -->
   ```
   `id` 必须是 `docs/tasks/<id>.json` 的 id。这一块是新任务的**唯一来源**：块外出现任何 `Task:` 行都会让启动器以 `EXIT=2` 停下并报出该行号。
3. 对话中输出**唯一**提示：**`执行 /newtask 开启新任务`**（Cline 会从本轮对话自动蒸馏并携带上下文）。
4. 立即停止一切读写，等用户切换会话。

### 7.4 新会话接棒（写死的四步，不可增删）
**入口：`npm run newtask`**（实现在 `scripts/handoff/newtask.mjs`，退出码即结论）。

1. **读 `HANDOFF.md`**（只读一次），取 `<!-- newtask -->` 块里的 `Task: <id>` 单行。缺块、块内多于一行、块外另有 `Task:` 行、id 非法、`docs/tasks/<id>.json` 不存在 → **一律 `EXIT=2` 立即退出**：不猜、不 fallback、不自动挑任务。
2. **`npm run budget -- --reset --task <id>`** 重开账本（由 `newtask.mjs` 调用，账本开不起来 → `EXIT=1`，不算启动成功）。
3. **从 `docs/tasks/*.json` 中选且仅选一个**——就是 `Task: <id>` 指定的那一个。
4. **只做它的断言**：`npm run task:verify -- <id>` 全绿即收工。已通过的断言不重跑。

**红线（其他任务的失败最多写进报告，不得顺手修）**
- **其他任务的失败最多写进报告，严禁顺手修**：其他 `docs/tasks/*.json` 的失败只能写进报告，严禁在本任务内改动它们的代码或断言。
- 改动任何与本任务断言无关的文件 = 越界。
- 发现自己想"顺手修"别人的失败时，先停下来问用户。

## 8. 严格遵守 Plan 和 Act 模式
- 所有较复杂的任务都先在 Plan 模式下完成：阅读代码、澄清需求、输出可执行计划，不得直接修改代码。
- 切换到 Act 模式后，必须严格按 Plan 阶段确认的计划执行，不得擅自扩展范围。
- 遇到需求不清、方案不确定或出现意外复杂度时，必须停止，再询问用户是否需要切回 Plan 模式重新规划，不得擅自再继续执行。

## 9. 主线任务约束
- 完成主线任务后立刻停止，仅将支线问题报告给用户，禁止擅自偏离主线继续执行。
- 每个任务用时最大30分钟，过时立刻停止。
- 只做 DoD 点名的事，__跑偏零容忍__：任何"顺手修"的失败（尤其图片/视频引用、其他 task 的断言失败）一律只写进收据「已知遗留」，禁止动手。
- 探索预算：单原子任务 ≤8 次工具调用；勘察类 ≤5 次；`npm run grep` 命中 ≤20。
- 临时探针文件收据前必须删除。
- 收据禁止以问句结尾，最后一行固定 `完毕，等待你的下一条指令。`
